TORKIS — Jak se ukládá podpis

Dynamický biometrický podpis s tamper-evident pečetí (AES-ekvivalent): plátno · Firebase Storage · Cloud Firestore

Co všechno se zaznamenává

Obrázek podpisu — PNG vykreslené z tahů; slouží do PDF protokolu a pro náhled.
Biometrie tahu — každý bod: souřadnice, čas, tlak a poloměr dotyku (dynamika podpisu).
Metadata prostředí — model zařízení, OS a verze, verze aplikace, jazyk, čas (UTC).
Pečeť (SHA-256) — hash obsahu zakázky + textu souhlasu; váže podpis na přesný dokument.

2. Kde přesně to leží

Firebase Storage — binární soubory v cestě:

Cloud Firestore — dokument zakazky/{servisId}_{zakazkaId}, tři nová pole:

4. Jak pečeť chrání před změnou

+ text souhlasu

rekurzivně seřazené klíče]
    B --> C[SHA-256]
    C --> D[(dokument_hash

    D -. při sporu .-> E{Přepočítat z aktuální
zakázky a porovnat}
    E -- shoda --> OK[Dokument nezměněn]
    E -- neshoda --> KO[Změna prokázána]
    style OK fill:#F0FDF4,stroke:#16A34A
    style KO fill:#FEF2F2,stroke:#DC2626
Kanonický JSON: klíče se rekurzivně řadí, takže stejný obsah dá vždy stejný hash bez ohledu na pořadí vložení. Bez toho by drobná změna serializace falešně „rozbila" pečeť.
Ověření při sporu: obsah zakázky (km, požadavky, poškození…) se znovu složí stejným způsobem, spočítá se SHA-256 a porovná s uloženým dokument_hash. Pokud se cokoli změnilo, hashe nesednou → změna je prokazatelná. Biometrii lze nezávisle ověřit proti biometrie_hash.

5. Plnění kritérií AES (eIDAS)

KritériumJak je splněno
Jednoznačná vazba na podepisujícíhoDynamika tahu — rytmus, rychlost, časování, tlak (u stylusu)
Schopnost identifikaceBiometrický profil + metadata zařízení a času
Detekce změny dokumentuSHA-256 dokument_hash vázaný na stvrzený obsah
Výhradní kontrola podepisujícíhoSplněno přibližně (data tahu pod fyzickou kontrolou); plné kritérium by vyžadovalo PKI pečeť servisu
Pozn. k tlaku: kapacitní displeje telefonů reálný tlak neměří — konstantu se filtruje a ma_tlak je pak false. Skutečnou hodnotu přinese aktivní stylus (Apple Pencil, S-Pen).

Shrnutí — kde je co

Obrázek podpisu — Storage podpis_*.png, odkaz v poli podpis_url.
Biometrie tahu — Storage podpis_biometrie_*.json, odkaz v podpis_data_url.
Pečeť a metadata — Firestore pole podpis_seal v dokumentu zakázky.
Integrita — dokument_hash + biometrie_hash; přepočítatelné a ověřitelné kdykoli později.

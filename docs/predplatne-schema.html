TORKIS — Jak fungují předplatná

Tok plateb a vynucení limitů: aplikace · Apple App Store · RevenueCat · Cloud Functions · Firestore

Aktéři

Aplikace (TORKIS) — klient; zahajuje nákup, vykresluje paywall, volá API.
App Store (Apple) — zpracuje platbu a obnovy/změny předplatného.
RevenueCat — vrstva nad Apple; drží stav entitlementů a posílá webhooky.
Cloud Functions — server: webhook (sync plánu) + volání Vincaria s tajným klíčem a limity.
Firestore — DB; predplatne = zdroj pravdy o plánu, pouziti = počítadlo limitů.
Vincario — externí placené API (VIN dekódování, tržní hodnota).

1. Tok nákupu předplatného

sequenceDiagram
    actor U as Uživatel
    participant A as Aplikace
    participant AS as App Store (Apple)
    participant RC as RevenueCat
    participant CF as Cloud Function (webhook)
    participant FS as Firestore

    U->>A: Klikne „Koupit Basic"
    A->>RC: purchasePackage(basic_monthly)
    RC->>AS: Zahájí nákup
    AS->>U: Potvrzení / platba (v sandboxu zdarma)
    AS-->>RC: Transakce OK
    RC-->>A: Entitlement „basic" je aktivní
    A->>A: Pustí dovnitř jako plán Basic
    Note over A,RC: Klient je aktivní okamžitě (čte stav z RevenueCatu)
    RC->>CF: Webhook (INITIAL_PURCHASE, entitlement_ids=[basic])
    CF->>FS: predplatne.plan_typ = basic
    Note over CF,FS: Firestore = zdroj pravdy pro SERVEROVÉ limity
Klient pozná plán hned z RevenueCatu. Server (limity drahého API) čte plán z Firestore, kam ho zapíše webhook — proto je potřeba obojí.

3. Vynucení limitů (VIN dekódování / tržní hodnota)

sequenceDiagram
    participant A as Aplikace
    participant CF as Cloud Function (decodeVin)
    participant FS as Firestore
    participant V as Vincario

    A->>CF: decodeVin(VIN)
    CF->>FS: Plán (predplatne) + počítadlo (pouziti)
    alt Limit vyčerpán
        CF-->>A: Chyba „měsíční limit vyčerpán"
    else VIN je v cache
        CF->>FS: Najde VIN v cache
        CF-->>A: Výsledek (nepočítá se do limitu)
    else Nový dotaz
        CF->>FS: Rezervuje slot v počítadle
        CF->>V: Zavolá Vincario (TAJNÝ sdílený klíč)
        V-->>CF: Data vozidla
        CF->>FS: Uloží do cache + počítadlo
        CF-->>A: Výsledek
    end
Proč přes server: tajný Vincario klíč je jen v Cloud Function, nikdy ne v aplikaci. Limit i počítadlo jsou na serveru, takže je nelze obejít úpravou aplikace.

5. Životní cyklus předplatného (upgrade / downgrade / vypršení)

Změny plánu řídí Apple. Server na ně reaguje webhookem a aktualizuje predplatne.

sequenceDiagram
    participant AS as App Store (Apple)
    participant RC as RevenueCat
    participant CF as Cloud Function (webhook)
    participant FS as Firestore

    Note over AS,FS: UPGRADE (Basic → Standard) — OKAMŽITĚ
    AS-->>RC: PRODUCT_CHANGE, standard hned aktivní (doúčtuje rozdíl)
    RC->>CF: webhook entitlement_ids=[standard]
    CF->>FS: plan_typ = standard

    Note over AS,FS: DOWNGRADE (Standard → Basic) — AŽ NA KONCI OBDOBÍ
    AS-->>RC: Změna naplánována, entitlement zůstává standard
    RC->>CF: PRODUCT_CHANGE entitlement_ids=[standard]
    CF->>FS: plan_typ = standard (beze změny)
    Note over AS,RC: …dožije do konce zaplaceného období…
    AS-->>RC: RENEWAL už na basic
    RC->>CF: webhook entitlement_ids=[basic]
    CF->>FS: plan_typ = basic

    Note over AS,FS: VYPRŠENÍ / ZRUŠENÍ
    AS-->>RC: Předplatné skončilo
    RC->>CF: EXPIRATION
    CF->>FS: platnost_do = minulost → při startu Paywall
AkceKdy se projevíCo udělá server
Upgrade (nahoru)Okamžitě (Apple doúčtuje rozdíl)Zapíše vyšší plán hned
Downgrade (dolů)Až při příští obnověDo té doby drží původní plán, pak přepíše na nižší
ZrušeníDožije do konce obdobíPo vypršení posune platnost do minulosti → Paywall
Pozn. k počítadlu: limity se počítají dle kalendářního měsíce, ale předplatné se obnovuje dle data nákupu. Když downgrade padne doprostřed kalendářního měsíce po vyšší spotřebě, může uživatel na nižší limit krátce „narazit" do konce měsíce; pak se počítadlo vynuluje.

Shrnutí — kdo je „zdroj pravdy"

Stav platby — Apple → RevenueCat. Appka se ptá RevenueCatu „má tenhle uživatel aktivní plán?".
Plán pro limity — Firestore predplatne.plan_typ, zapisuje webhook nebo vlastník v konzoli.
Počítání limitů — Firestore pouziti, zapisuje výhradně server (Cloud Function).
Tajný API klíč — pouze Cloud Functions (Secret Manager), nikdy v aplikaci.

Jak aplikace komunikuje s Firebase a Google Cloud
Verze aplikace 5.3.2 · Stav k 6. 6. 2026 · Projekt Firebase visto-51cb7 · Region funkcí europe-west3

Tento dokument popisuje, s jakými službami aplikace TORKIS komunikuje, jaká data z nich čte, jaká do nich zapisuje, kudy tečou citlivé klíče a jak je vše zabezpečené. Je psaný tak, aby byl srozumitelný i bez znalosti zdrojového kódu.

Legenda značek u dat: ČTE aplikace čte   ZAPISUJE aplikace zapisuje   ČTE+ZAPISUJE   SERVER-ONLY přístup jen ze serveru (Cloud Functions)

1. Přehled architektury

Aplikace je klient (Flutter — Android, iOS, web/Windows) a sama o sobě neukládá žádná byznys data lokálně natrvalo kromě drobných uživatelských preferencí. Veškerá data žijí v cloudu Google/Firebase. Drahá a citlivá volání (placená VIN API) nejdou z aplikace přímo, ale přes Cloud Functions, které jediné drží tajné klíče.

Obr. 1 — Aplikace mluví hlavně s Firebase. Placená VIN/STK API a tajné klíče jsou schované za Cloud Functions; jen ARES, ČNB a přihlašovací poskytovatelé jdou z klienta přímo.

5. Cloud Storage — binární soubory

Soubory se ukládají do stromu podle servisu a zakázky:

servisy/{servis_id}/zakazky/{cislo_zakazky}/
   ├── <kategorie>_<n>.jpg      — fotografie z příjmu (interiér, poškození, VIN…)
   ├── schema_poskozeni.png      — nákres poškození
   └── protokol_{cislo}.pdf      — vygenerovaný protokol o příjmu

Aplikace soubory nahrává (foto, PDF, schéma) a později čte jejich veřejné odkazy, které ukládá do dokumentu zakázky (fotografie_urls, podpis_url). Zákaznický portál pak fotky a PDF zobrazuje z těchto odkazů.

6. Cloud Functions — serverová logika

Funkce běží v regionu europe-west3. Jsou jediným místem, kde žijí tajné klíče (Firebase Secrets) — v aplikaci nikdy nejsou.

FunkceTypCo dělá / čte / zapisuje
decodeVincallableDekóduje VIN přes Vincario. Ověří uživatele → servis_id → plán. Čte/zapisuje vin_cache, rezervuje slot v pouziti (měsíční limit). Při cache-zásahu API nevolá.
marketValueVincallableZjistí tržní hodnotu vozu přes Vincario. Stejná logika, cache value_cache, limit pouziti.
stkVincallableNačte STK a technická data z api.dataovozidlech.cz. Cache stk_cache na 24 h. Bez měsíčního limitu, jen ověření přihlášení.
revenuecatWebhookHTTPPřijímá události o nákupu/obnově od RevenueCat a zapisuje důvěryhodný plán do predplatne. Chráněno tajným tokenem v hlavičce.
deleteZamestnaneccallableÚplné odstranění člena týmu — smaže Auth účet i profil v uzivatele. Ověří, že volající je správce stejného servisu a nemaže sám sebe.
Tajné klíče (Firebase Secrets), jen na serveru: VINCARIO_API_KEY, VINCARIO_SECRET, DATAOVOZIDLECH_API_KEY, REVENUECAT_WEBHOOK_AUTH.
Proč přes server? Vincario je placené za volání. Kdyby klíč byl v aplikaci, šel by z dekompilované aplikace vytáhnout a zneužít. Server navíc tvrdě vynucuje měsíční limity dle plánu a cachuje výsledky, takže stejné VIN se neplatí dvakrát.

8. Bezpečnostní model (shrnutí)

Detailní rozbor je v samostatném dokumentu „Bezpečnostní pravidla Firestore". Klíčové zásady:

  • Vše zakázáno, dokud pravidlo výslovně nepovolí (deny by default). Server-only kolekce nemají žádné povolení pro klienta.
  • Izolace servisů — každý dotaz i zápis prochází kontrolou servis_id; uživatel nevidí cizí servis.
  • Oprávnění modulů — člen týmu má v profilu prava a aplikace mu zpřístupní jen povolené moduly.
  • Citlivá pole se nedají podvrhnout — uživatel si nesmí přepsat servis_id, role ani prava; placený plán zapisuje jen RevenueCat webhook.
  • Zákaznický portál běží na anonymním přihlášení a vidí jen jednu zakázku přes její portal_token; smí přidat zprávu a schválit/zamítnout nacenění, nic víc.

9. Příklady toku dat

9.1 Příjem vozidla (vytvoření zakázky)

  1. Mechanik vyfotí vůz → ML Kit lokálně přečte VIN/SPZ (bez odeslání fotky).
  2. Volitelně decodeVin / stkVin doplní technická data (přes funkce, s cache a limity).
  3. IČO zákazníka se ověří v ARES (přímo).
  4. Fotky, schéma a vygenerované PDF se nahrají do Storage.
  5. Vznikne dokument v zakazky (+ aktualizace vozidla a zakaznici).
  6. Při zapnutém odesílání e-mailu se založí dokument v maily → extension odešle protokol zákazníkovi.

9.2 VIN dekodér

Aplikace zavolá decodeVin. Funkce nejdřív zkusí vin_cache; při zásahu vrací data zdarma. Jinak rezervuje slot v pouziti (kontrola limitu plánu), zavolá Vincario tajným klíčem, výsledek uloží do cache a vrátí. Historie se ukládá do vin_skeny.

9.3 Předplatné

Nákup probíhá přes RevenueCat SDK v aplikaci. Skutečný plán ale do predplatne zapisuje až server přes revenuecatWebhook — aplikace plán „povýšit" nemůže. Limity API se pak odvozují z tohoto důvěryhodného plánu.

9.4 Zákaznický portál

Zákazník otevře odkaz /zakazka/<token> na Hostingu, aplikace ho přihlásí anonymně a podle portal_token načte jednu zakázku. Může číst stav a zprávy, přidat dotaz a schválit/zamítnout nacenění (subkolekce zakaznik_zpravy).
